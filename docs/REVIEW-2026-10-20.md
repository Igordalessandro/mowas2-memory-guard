# Experimental development review — 2026-10-20

Development version: `2.5.0-experimental.9-dev`, based on released
`v2.5.0-experimental.8` (`a5f5a05`). The published releases and installed game
copies are separate from this work. Stable remains `v2.4.2`.

Publication: these reviewed changes are included in
`v2.5.0-experimental.9`. The development artifact checksum below is retained
as review history; use `SHA256SUMS-v2.5.0-experimental.9.txt` for the release.

## Field evidence and scope

The public report source is this
[Steam discussion](https://steamcommunity.com/app/244450/discussions/0/591817814333171584/).
Both pages were read during this review. The latest crash report there still
identifies experimental.6; no experimental.8 result was available at review
time. The RobZ report accounts for approximately 4 GiB of process VA, with
55 MiB free in total and only a 4 MiB largest hole. That evidence supports
exhaustion/fragmentation. It does not establish a leak, nor identify which
live game resources can safely be discarded.

This review fixes bounded implementation defects and improves the evidence
available for the next investigation. It does not raise the x86 address-space
ceiling or claim that the heavy-mod scenario is solved.

## Implemented changes

### Recovery ownership and publication

Experimental.8 published a rebuilt recovery pointer before clearing its old
retry metadata. A second thread could release that pointer and set a new
retry owner, only for the rearming thread to erase that state. The production
`RecoveryState<Mutex>` now serializes release, owner authorization, and rearm
publication as complete transactions. Windows uses an SRW lock. The rearm
path skips a busy lock and leaves later attempts to the monitor.

The native regression pauses the actual production rearm callback and
coordinates a competing release to verify that the new retry owner survives.
It also covers failed release, non-owner confirmation, failed rearm, and
changing reservation sizes. Reserve sizes and release thresholds remain the
experimental.8 values.

The requested-byte snapshot also uses an atomic 64-bit load, avoiding a torn
read on x86.

### Allocator behavior and useful sampling

- `VirtualAlloc` recovery is limited to new-range allocation failures with
  memory-exhaustion errors. Invalid parameters/addresses, `MEM_RESET`, physical
  mappings, and commits inside existing ranges no longer drain emergency VA.
  Ordinary non-recoverable failures log only the first four occurrences.
  Resource-exhaustion errors still enter the report and flight recorder when
  reserve release cannot help, including Windows commitment-limit failures.
- Allocator wrappers restore the native call's error code after telemetry.
  Every retry receives the caller's original error state.
- Sampled records are detached before native free/realloc can make an address
  available for reuse. A failed operation restores its old record; a success
  retires that exact identity, rather than potentially deleting a new
  allocation at the same address.
- Global sampled live bytes are maintained independently of the site table.
  Sampled records retain their original site pointer for later retirement.
  Filling the call-site table no longer freezes the global estimate.
- A per-thread caller cache keeps frequent sites cheap. After saturation,
  existing-site lookups inspect at most 16 slots and new sites are not added.
  Rankings can still be incomplete: saturation and sampling are not evidence
  that the top listed site owns every live allocation.
- Failed free/realloc restores sample lifetime without inventing a successful
  free. If diagnostic bucket space is lost meanwhile, only the diagnostic
  sample is dropped and counted.
- IAT rollback keeps native function pointers valid for threads already
  executing a wrapper.

These wrappers continue to use the original allocators and never shrink valid
requests. The known lobby sentinel remains the only size substitution.

### Long paths and bounded disk activity

All seven file wrappers now preserve native errors after path destruction and
diagnostics, including successful `CreateFile` calls returning
`ERROR_ALREADY_EXISTS`. Short relative names are considered for rewriting
when the working directory makes the resolved path long. Ordinary short
absolute paths remain allocation-free.
Root-relative paths under a UNC working directory retain their server/share
root. Drive-relative `C:foo` inputs remain native pass-through calls.

Repeated missing long-path resource probes are counted but only the first
events and sparse later failures are logged. A regression sends 10,000
missing probes and checks that output stays bounded and the compact event is
not rewritten on every probe. This addresses avoidable I/O directly.

### Crash evidence

- The previous compact and emergency reports are copied to exact
  `.previous.txt` paths before a new session replaces them. If the backup
  fails, the original report is left untouched and detailed logging continues.
- The compact formatter is allocation-free, ASCII-only, and capped at 900
  bytes. It appends complete lines and prioritizes session/crash/failure/memory
  over optional details. `omitted=optional_fields` points readers toward the
  full log when the budget is exhausted.
- The exception filter attempts the logger lock without waiting for another
  thread. It always writes a stack-formatted minimal report to a separately
  preopened emergency handle before entering normal CRT formatting.
- The game's previous exception filter is still chained after releasing the
  logger lock. Engine-handled fatal errors may never reach an unhandled
  exception filter; `crash=not_captured...` is not proof of a healthy session.

### dbghelp readiness

The startup worker resolves real `ImageNtHeader` and `MiniDumpWriteDump`
before the emergency reserves and allocator hooks. This avoids requiring the
first DLL load during an allocation crisis. Editors retain lazy proxy-only
forwarding. Forwarders preserve caller error state and do not use partially
published function pointers.

If another process maps the fixed temporary system DLL, sharing-violation
reuse now requires an equal-size, full-content comparison against the current
system DLL. The comparison uses fixed buffers, denies concurrent writers,
and refuses unreadable, empty, different, or excessively large files.

## Validation

Portable tests run with strict warnings, then with AddressSanitizer and
UndefinedBehaviorSanitizer. Windows regression executables compile for i686
with `-Wall -Wextra -Wconversion -Werror`. The complete development DLL is
built separately under `dist/v2.5.0-experimental.9-dev/`, leaving the
experimental.8 artifact untouched.

Development artifact SHA-256:

```text
12b4a6257cc19224f5a2b46eb752d801181c73e0694b458a7144522b604b29cf
```

Windows suites exercise the actual production wrappers with substitutes for
the native delegates. They cover allocator recovery/errors/address reuse,
file preparation/errors/log volume, exception filter fallback/chaining,
report preservation, and system-copy comparison. VAC policy tests check
secure rejection and insecure argument/return forwarding without contacting
Steam or installing hooks. They do not prove live Steam/Proton ABI behavior.

Windows binaries were cross-compiled on Linux during this review, not
executed. The committed workflow and `tests/run-windows.ps1` provide native
Windows execution on a subsequent push. Neither games nor Wine/Proton were
launched to test these changes.

## Follow-up research with a clear stopping point

1. Obtain the detailed log matching the RobZ PID/version before retuning the
   reserve sizes again. Compare recovery release/rearm, failed request, largest
   hole and heap events. Repeat the same map/settings for useful comparisons.
2. Ask long-path reporters for `LONG PATH` events. API success with continued
   multiplayer rejection points toward resource identity/internal buffers;
   absence of events can mean truncation before the API boundary. Do not
   globally patch guessed 255-byte constants.
3. Classify growing committed content from one detailed native Windows and
   one Proton session. Sampling identifies investigation sites; it does not
   authorize freeing the game's still-owned objects.

Deferred larger or separate work: replacing the engine allocator, renderer
resource offloading, a true x64 conversion, internal engine buffer-layout
changes, and broad Steam-interface interception. The review also observed
that logger/proxy installation-directory buffers still use `MAX_PATH`, and
that join-guard installation has a startup interval while waiting for Steam.
These limitations should remain explicit rather than promising absolute
startup protection or universal long-path support.

VAC host/join refusal policy and fail-closed installation behavior are
preserved. No anti-cheat bypass or assurance against account penalties is
introduced by these development changes.
